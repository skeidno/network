远端用户

多会话并存的关键

系统默认 fSingleSessionPerUser=1，意思是同一个用户名只允许一个远程会话 —— 用 Administrator 连过一次，再用同名账号连就会把上一次踢掉。这也是为什么「加一个子用户」能让内网连接正常工作：不同用户名 = 不同会话，可以并存。

统一中转
所有出站先经过它，再连真正的节点

              

                
              

              

                
              

              
本地直连某些节点会被掐、被限或干脆连不上，但中转那台机器能连上 —— 中转通常就是自己买的服务器或 ISP。它只有这一个，不用逐个节点去配：开启后所有节点自动挂上代理链（内核的 dialer-proxy），中转自己除外，否则会无限套娃。指向本机回环的节点（另一个客户端的端口）也不走中转 —— 那台远端机器去连的会是它自己身上的 127.0.0.1，必然连失败。本程序、浏览器、以及挂本地代理端口跑的代码，走的都是同一条链路，不会出现「测速通但用不了」这种两套结果。中转节点本身仍然可以当普通节点用，只是不再经过任何前置。

            

            

              
本地 DNS
DNS 应答模式与自定义域名映射

              

                
              

              
              
写进内核的 hosts 表，命中即返回，不会往外发查询 —— 局域网里的 NAS、路由器、自建站点因此能直接用域名访问。写成 *.baidu.com 就是通配：baidu.com 本身和它的所有子域都算，只写 nas.lan 则只匹配这一个名字；地址属于内网网段时会自动直连。要在局域网里跑 HTTPS，证书里的名字得和这里的域名一致 —— 下面的「本地证书」会按这张表自动签，不用自己去开 openssl。浏览器与系统的「安全 DNS / 私人 DNS」会绕过这张表，属于预期行为。

体检只做只读检查：直接问各工具自己的 --version，问不到再查注册表和默认安装目录。不下载安装包、不改注册表、不动 PATH。缺什么就交给官方包管理器 winget 去装，命令与输出原样显示在这里 —— 出了问题你能自己判断是哪一步的事。
「版本过旧」和「缺失」是两回事：过旧的项已经装上了，只是低于本项目实际需要的版本（比如 Node.js 要 20、JDK 要 17、WebView2 要 90），重装会先尝试 winget 升级，升级不可用才退回强制重装，所以它只出现在单张卡片的「重装升级」按钮里，不进「一键部署」的批量流程 —— 那个按钮只管真正缺的东西。
Node.js 走 nvm 管版本：能同时并存多个版本，点已装版本的徽章即可切换，互不影响。切换后新开的终端才生效 —— nvm 是靠改软链接实现的，已经开着的窗口里跑的还是旧版本。
Python 只认原生安装（python.org 官方包或 Microsoft Store），不使用 conda 环境里的解释器 —— 那个解释器依赖 activate 才生效，直接查它拿到的版本不代表你命令行里实际在跑的那个，而且我们只体检单个解释器、管不了 conda 的依赖包。其它工具同样不能并存，装指定版本会先卸载现有的，所以点了会先问一次。
