# Network Manager v0.6.10

自 v0.6.6 以来共 29 个提交。主线是**产品代码全部 Rust 化**，外加 Windows 桌面端托盘与窗口行为的一批修复。跨设备配置格式与已有分流规则行为不变。

## Windows 桌面端

- **托盘点击唤回与右键菜单修复**。根因不是 Win11 托盘溢出区的平台限制，而是代码问题：explorer 用 `SendMessage` 把托盘消息直投窗口过程（不进 `GetMessageW` 队列），且通知码在 `lParam` **低位字**（`NIN_SELECT` 实际收到的是 `0x00010400`），此前这些消息被 `DefWindowProc` 丢掉了。右键菜单改为 `PostMessage` 回消息泵后再弹，避免在 explorer 的调用栈内 `TrackPopupMenu` 把资源管理器卡死。
- **关闭窗口的行为改为「关闭界面 + 退到托盘继续运行」**：任务栏按钮消失，进程与内核保留，托盘单击可唤回。窗口隐藏会销毁承载输入的 `Chrome_RenderWidgetHostHWND`，唤回时重建 WebView。设置页提供「退出并停止接管」按钮，托盘菜单的退出仍是真正退出进程。
- **修掉设置页开关保存后不生效**：前端传 camelCase（`closeToTray` / `strictRoute`），`AppConfig` 是 snake_case，合并前没做键名转换，导致返回 200 但值不变。
- 事件循环崩溃不再退回「开浏览器 + 等 Ctrl-C」的兜底路径，改为收掉内核后退出。
- 服务器部署改为表格视图，支持批量操作。
- 只清理真正的内核孤儿进程，启动前先确认单实例；二次启动唤醒已运行实例。

## Linux

- **Linux 侧从 Python headless 换成 Rust 常驻服务**。原生界面（tao + wry）限定为 Windows 依赖，Linux 编出的是**没有图形栈依赖**的单文件二进制，由 systemd 托管，管理页面用浏览器打开。
- 安装脚本去掉 python3 / venv / pip，直接部署 `network-manager-rs`；systemd 单元的 `ExecStart` 指向 `/opt/network-manager/bin/network-manager-rs`。口令生成改用 openssl（退回 `/dev/urandom`）。
- **修掉 Linux 上点「导入文件」会调用不存在的 `importFile`**：Rust 侧没有原生文件对话框，只有浏览器读文件后回传内容的 `importFileText`，而 `capabilities.browserFiles` 此前恒为 `false`。同时 `headless` 在 Linux 上恒为 true，避免界面露出「开机自启 / 关闭到托盘」这类只有桌面端才有意义的设置。

## 工程

- **仓库里的 Python 代码全部退场**：`src/network_manager` 下的 Python 模块（5054 行）、13 个 Python 测试、Windows 桌面 GUI（PySide6，6389 行）都已删除。发布打包脚本改为 bash（`scripts/build_linux_release.sh`）与 PowerShell（`scripts/build_windows_installer.ps1`，内核下载与校验已合进其中）。现在 `git ls-files "*.py"` 为空。
- 原先 `tests/test_linux_packaging.py` 的契约断言迁到 `rust/tests/linux_packaging.rs`，走 `cargo test`，回归保护没有跟着 Python 一起消失。
- CI：Windows 上 `cargo check` + `clippy` + PowerShell 语法检查；Linux 上 `cargo build` + 真实冒烟（起服务、HTTP 应答、SIGTERM 后必须退出 0，即 `systemctl stop` 那条路径）+ 打包 amd64 安装包 + `cargo test`。
- 顺带修掉：Windows 安装器脚本一直在读**已删除的 `pyproject.toml`**，改为读 `rust/Cargo.toml`。

### 关于 Android

`NetworkManager-Android-v0.6.10.apk` 本次**未提供**。签名密钥（`network-manager-release.keystore`）被 `.gitignore` 排除、不在仓库里，构建环境拿不到，`docs/RELEASE_POLICY.md` 又明确禁止用 debug APK 顶替。

发布流水线已经把这条路铺好：只要把下面四个仓库密钥配上（`Settings → Secrets and variables → Actions`），下次打标签就会自动出正式签名 APK，无需改代码。

| Secret | 内容 |
| --- | --- |
| `ANDROID_KEYSTORE_BASE64` | `base64 -w0 network-manager-release.keystore` 的输出 |
| `ANDROID_KEYSTORE_PASSWORD` | keystore 口令 |
| `ANDROID_KEY_ALIAS` | 密钥别名（当前为 `network-manager`） |
| `ANDROID_KEY_PASSWORD` | 密钥口令 |

Android 包版本号已改为可由流水线注入（`-PappVersionName`），默认 `0.6.10` / `versionCode 8`，与本次标签一致。

按 `docs/RELEASE_POLICY.md`，必需产物缺任何一件都不得标记为正式发布，因此本版在 APK 补齐前标记为**预发布**。

已知待办：Linux 侧只做过 CI 冒烟，TUN 接管、订阅刷新、节点测速、SSH 部署尚未在真机验证。
