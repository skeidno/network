# Network Manager v0.6.15

补丁版，只修一件事：**代理出口检测失败时报的错会指向错误的方向**。

## 问题

节点整条不通时，检测会报：

```
代理出口检测失败：所有出口检测端点均失败：
http://ip-api.com/json/: HTTP status server error (502 Bad Gateway) for url (http://ip-api.com/json/)
```

看着像是那些 IP 检测站点挂了，于是去折腾端点——但真正坏的是**当前选中的节点**：
mihomo 拨不通上游节点时，对经过它的 HTTP 请求统一回 502/503/504，reqwest 再把状态码
连同 URL 一起抛出来，就成了上面这句。

## 修法

1. **先做节点预检**：代理出口检测前，先对当前选中的节点做一次 TCP 握手（最多 3 秒）。
   不通就直接报「所选节点『XXX』连不上，换一个节点再试」，不再让 8 个检测端点各等
   12 秒超时、最后汇总成一句看不懂的话。
2. **502/503/504 归类成节点问题**：预检通过但最终还是拿到 502 时，报
   「内核连不上当前节点（返回 502），换一个节点再试」，而不是把它算在端点头上。
3. **端口没监听单独说**：连接被拒时是「本地代理端口没有监听，接管可能已经停止」，
   跟「节点不通」区分开。
4. **清掉噪声**：不再输出 reqwest 那串 `HTTP status server error (...) for url (...)`。

直连出口检测不受影响（不走代理就没有 502 这回事），措辞保持原样。

## 顺带说清一件事：批量测速「通」不等于能代理

批量测速测的是**到节点的一次 TCP 握手**。像 `主机:端口:用户名:密码` 这类节点，握手
常常是通的（端口在监听），但实际发请求会被立刻断开 —— 这类节点在测速列表里看起来
是正常的，选上之后却什么也打不开。

测速结果请当作「端口可达」，不能当作「代理可用」。真正的验证是选上它之后做一次
出口 IP 检测。

## 产物

本版由 `.github/workflows/release.yml` 在打标签时自动构建，产物同源（同一个标签、同一个提交）：

- `NetworkManager-Setup-x64-v0.6.15.exe`：Windows x64 安装包（内含 Rust 单文件 exe、`mihomo.exe` 与 `wintun.dll`）。
- `NetworkManager-Linux-amd64-v0.6.15.tar.gz`：Linux amd64 无界面 WebGUI 服务包。
- `NetworkManager-Linux-arm64-v0.6.15.tar.gz`：Linux arm64 无界面 WebGUI 服务包。
- `SHA256SUMS.txt`：上述成品的 SHA-256 校验值。
