# v0.6.16

## 修复：接管「看起来开着」其实一条流量都没接管

这是本次最重要的一处修复，也是「节点都挂着，出口 IP 却是本地的」的直接原因。

内核（mihomo）起 TUN 失败时**不会退出**，只往日志里打一条：

```
level=error msg="Start TUN listening error: configure tun interface:
                set ipv4 address: The object already exists."
```

然后继续正常跑：混合端口照常监听、进程活着、界面显示接管中。
而在此之前，本程序判断接管是否正常的唯一依据就是「内核进程活着」——
于是这一路全是绿灯，**没有任何一处会发现接管其实没生效**。
用户能看到的只有结果：代理开着、节点挂着一串，查出口 IP 却还是本地的。

这次改了三件事：

1. **认得出**。内核启动时会记下日志位置，之后只对「本次启动新增的日志」做判断。
   一旦发现 `Start TUN listening error`，就认定接管没有真正生效。
2. **能自愈**。先把上次异常退出残留的 wintun 网卡删掉
   （残留不清理，重启内核只会原样再失败一次），再重启内核。
3. **会说话**。明确提示「接管没有真正生效（<内核给的原因>），已重启内核重试」，
   而不是像以前那样沉默。

触发这种残留的典型场景：内核进程崩溃或被强杀，wintun 网卡没释放干净，
下次启动就撞上 `The object already exists`。

## 修复：批量测速的「通」现在是真的通

之前测速只做一次 TCP 握手：端口能连上就算通。对代理商批发的住宅代理来说，
端口一律开着，握手毫秒级成功，可一旦真的发 CONNECT 就被对端掐断。
于是界面显示「测速全通」，实际一个都代理不出去——这两件事在旧版里无法区分。

现在按协议分层验证：

| 节点类型 | 验证方式 | 说明 |
| --- | --- | --- |
| http / https | 发真实 `CONNECT 1.1.1.1:443`（带 `Proxy-Authorization`），读到 2xx 才算通过 | 407 单独报「代理拒绝了账号」 |
| socks5 | 发 SOCKS5 握手，能协商出方法才算通过 | 返回 `0xFF` 报「不接受匿名连接」 |
| vless / vmess / trojan / ss 等 | 仍为 TCP 握手 | 端到端加密，本机没有密钥，握不了手 |

也就是说：**http 节点显示「通」，现在代表它真的能把连接递出去**，
不再只是端口可达。测速耗时略增（多一次往返），但结论可信了。

## 升级说明

- 装上后如果发现接管其实没生效，程序会自动重启内核恢复，并弹出提示。
  看到这条提示说明这次接管是从故障里恢复的，不是新故障。
- 测速结果会比以前更容易出现「失败」：这不是新 bug，是以前被握手假象
  掩盖的问题现在暴露出来了。仍显示失败的节点，需要找供应商核对账号授权
  与出口白名单。
