# Network Manager v0.6.14

补丁版，修两个影响日常使用的问题：**接管核心反复起不来、界面每 15 秒弹一次「核心异常退出，已自动恢复」**，以及**批量测速慢**。

## 一、核心起不来：一条空规则把整个接管打死

内核日志里反复出现同一条致命错误：

```
level=fatal msg="Parse config error: rules[31] [DOMAIN-SUFFIX,,IMPORTED-NODES]
error: missing subsequent parameters: DOMAIN-SUFFIX"
```

`DOMAIN-SUFFIX` 后面空空如也，mihomo 读配置就退出。mihomo 不像别的配置项那样「跳过这一条」，**整个接管都起不来**，于是自愈守护每 15 秒重新拉一次、每 15 秒失败一次，界面就跟着每 15 秒弹一次同样的提示。

### 这条空规则是怎么来的

界面「添加规则」提交的是表单结构 `{index, ruleType, values: [...], target, note, enabled}`，后端却直接把它 `serde_json::from_value::<RoutingRule>` —— 而结构体字段是单值的 `rule_type` / `value`，名字对不上。

`RoutingRule` 带 `#[serde(default)]`，所以 serde **不报错**，只是把认不出的键丢掉、其余补默认值 → 存下来的是一条 `rule_type=DOMAIN-SUFFIX, value=""` 的空规则。

更糟的是前端只传了一个参数，`index` 在后端读的是 `args[1]`，永远取不到 → 不管添加还是编辑，**都写到第 0 条规则上**。所以那次「添加规则」既留下一条空规则，又覆盖掉了原来的第一条。

### 修法（四层，任一层都能挡住）

1. **表单显式解析**：`rules_from_patch()` 按 `ruleType` + `values[]` 解析，一行一条展开成多条规则，空值与重复项去掉；`index` 从表单里读（负数或缺失 = 新增），编辑时插回原位置而不是覆盖第 0 条。
2. **渲染兜底**：生成内核配置前过滤掉 `rule_type` 或 `value` 为空的规则 —— 一条半成品规则不该把整个接管打死。
3. **加载清洗**：读到旧配置里的空规则直接丢弃并落盘，不需要用户自己去列表里翻。
4. **自愈守护**：拉起后等一小会儿确认进程真活着（`start()` 成功只代表创建成功，配置有错时它毫秒级就退出了），死掉就把内核日志里的 `fatal` 原文带进提示；失败只提示一次、之后安静退避；「已自动恢复」也限制两分钟内最多一次，不再刷屏。

顺带修了 `ruleAction` 的参数顺序：前端传 `(index, action)`，后端按 `(action, index)` 读，结果切换/删除规则一律报「不支持的规则操作」。现在两种顺序都兼容。

**如果你之前用界面加过分流规则**，那条规则很可能已经被写成空规则、并且覆盖了当时的第一条。升级后空规则会自动消失，需要的话重新添加一次即可。

## 二、批量测速慢

`run_node_tests` 原本是**串行**的：一个节点一次 TCP 握手，连不上的节点要等满 3 秒超时。几十个节点里有一半连不上，总耗时就是几十 × 3 秒，接近两分钟，看着像卡死。

改成**有界并发**（同时最多 16 个握手在飞）：同样一批节点，最坏情况从「N × 3 秒」降到「N / 16 × 3 秒」，百来个节点从约五分钟压到二十秒级。每测完一个立刻回写并放锁，界面照常轮询，结果一条条刷出来。

## 验证

- 新增 5 条单测：表单 `values[]` 解析（含去重去空）、空值与非法去向被拒、旧的单值 `value` 写法仍兼容、空规则不会进内核配置、`is_complete` 判定。
- `cargo test` 全绿（57 + 4 契约测试）。
